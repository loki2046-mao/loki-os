这套排版我前后做了几版：独立 HTML 编辑器、server 端 Python 引擎、再到配色组件化。难的地方在于粘贴进微信后台之后还能剩多少，排得好看倒在其次。

01 两套实现先摆在一起评

2026-04-14 我把 v12/v13 独立 HTML 编辑器和 editor_server.py（端口 8789）逐项摆在一起比：飞书导入、块编辑、渲染质量、复制方式。比下来的结论是统一到 server 端，Python 引擎排版质量更高，微信净化也更容易在渲染层做。

02 微信不认的东西列成一张清单

微信后台不支持 flex、不认渐变和圆角、div 时有时无、data URL 的图片直接被拒，这些我一条条试出来列成清单，净化方案也写成规则：容器换成带 display:block 的 span 或 p，flex 改 table 布局，渐变回纯色，图片必须给公网 URL。Callout 展开/收起测完直接放弃，微信不支持任何 JS，固定展开的高亮块是唯一解。

03 细节上认输，但要记下来

圆角粘贴后会丢，评估下来的结论是【不影响布局，建议放弃】；图片大小调整索性不做，微信后台里宽度由容器百分比控制，调了也白调。多图画廊的分行规则倒是完整的：四张排 2+2，五张排 3+2。

04 排版质量继续迭代，配色组件化

7 月第三期我把 Loki 配色体系接进组件库，第四期嫁接摸鱼小李的设计语言，同一篇蔡依林文章留下 mocha、焦糖、午夜金、noir、酒红五个配色版本横向对照。2026-07-05 的 CHANGELOG 记着这批脚本从旧工作目录迁进 loki-wechat-pipeline，路径全部改成自包含。
