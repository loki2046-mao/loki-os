# 踩坑记录 · 精灵图与缓存（2026-09-17）

来源：中场休息页「桌宠椰子」彩蛋（`assets/coconut-pet.js` + `assets/skills/coconut/*.png`）。
记下来只为下次别重踩，改动前先看这份。

## 坑一：精灵图的行距不能按「图宽 ÷ 列数」假设

**症状**：椰子走动时帧与帧之间上下抖动、脚被裁掉一截，看着像卡顿和抽搐；按下均分网格切出来的格子越往下偏得越多。

**实情**：`assets/skills/hatch-pet.webp`（1200×1788）**不是**等距网格。
- 实测各行动作的内容带：y = 4 / 168 / 330 / 492 / 654 / 818，**行高 154、行距约 162.6**；
- 若按 1788 ÷ 12 = 149 当行高，第 9 行就已经偏出约 37px，越往下越离谱。
- 水平方向才是规则的：帧宽 150。

**做法**：用 alpha 通道逐行/逐列扫描实际内容带，别信肉眼和均分。
本次已把六条动作条裁成独立小图（`assets/skills/coconut/{idle,left,right,wave,jump,sleep}.png`，均 1200×154），
顺带把参与合成的图层从整张 1200×1788 缩到 1200×154。

**顺带一条**：帧数同样靠实测，别照文档抄。这里 wave 4 帧、jump 5 帧、idle 7 帧、走 8 帧、睡 8 帧。

## 坑二：同名图片换内容必须带版本号，否则改了等于没改

**症状**：图集内容已经换过一轮（左右朝向对调），本地验证通过，用户浏览器里还是旧行为，看着像「改了没生效」。

**根因**：文件名和 URL 都没变，浏览器（以及可能的 CDN）继续用缓存的旧图。

**做法**：精灵图换内容时，同步改 JS 里的版本号常量：
```js
const VER = '?v=20260917c';   // 换图必须改这里
```
图片预加载和 `background-image` 都拼上 `VER`；引用该脚本的 `index.html` 里的 `<script src>` 也带同一个版本号。
换图 = 改文件 + 改版本号，两件事一起做。

## 附：这次验证方式（以后照做）

- **朝向**：连采样一个完整溜达周期，比对「位移方向」与「当前动作条」，统计一致/相反条数（本次 48/48 一致才算过）。
- **两个轴都要验**：气泡那次只验了左右没验上下，结果桌面端被 `overflow:hidden` 切掉头顶。判定一律用 `getBoundingClientRect()` 对容器做四边比较。
- **动画平滑**：位移与换帧只走 `transform: translate3d(...)`（合成层），不要动 `left` / `background-position`，那是每帧重排重绘。
