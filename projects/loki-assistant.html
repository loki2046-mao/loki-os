CALL SHEET / 研发过程
CALL SHEET / THREE PHASES AND BEYOND时间与证据分开记录
01 / 2026-05-23 起

先有桌面端骨架，再立 PRD

本地仓库首条 commit 是 2026-05-23 的「全面优化：单实例 Tauri、MD 渲染、记忆反馈、搜索、时间戳等 10 项」——先跑通桌面壳，再想清楚产品。PRD 第一行写的就是定位：「一个真正属于 Loki 的 AI 助手。透明、可控、记住你、能干活」，并明确「不是套壳工具，不是聊天机器人」。私有仓库 2026-06-17 建立。

证据：本地仓库首条 commit 与 PRD.md
02 / 2026-06-21 — 07-03

阶段一到阶段三：能跑、有记忆、接 Obsidian

按 PRD 的三个阶段推进：Next.js 框架加对话界面先跑起来；SQLite 记忆库按事实、模式、历史、碎片四类建表，对话结束后异步提炼写入，开始前按相关性检索进 context；然后接 Obsidian——扫描本地 vault 全部 Markdown 建全文索引，搜索时能从笔记里捞相关内容。这三步的 commit 密集落在 6 月下旬到 7 月初。

证据：仓库 commit 时间线（阶段一~三），2026-06-21 至 07-03 密集提交
03 / 2026-07-04 — 08-06

从单模型走向多模型，弱模型也要兜得住

模型不能绑死一家：provider 限流不再判死刑，重试打满自动降级备用渠道，报错要说人话；加上 provider 体检和 MCP 双向接入。渠道配置保存在本地，页面上 Key 不回显。到 8 月，模型目录、默认渠道、健康检查都成了界面里能操作的东西。

证据：commit「限流不再判死刑」「MCP 双向接入」等，2026-07-04 / 08-05
04 / 2026-08 起

Agent Core v1：会干活，还要干得可解释

工具调用循环落成 Agent Core v1：工具 trace 留痕可回看；防幽灵写入的不变量锚定本地目录；检测到相同调用反复卡死就主动熔断，不再烧预算；宣称完成的产物路径先到磁盘上验证过才算数。早报、晚报、周回顾和文件库、项目容器也在这段时间长出来，桌面端和网页端同步演进。

证据：Agent Core v1 相关 commit 与 docs/core/agent-architecture-v2.md

能用但仍需维护

  • 私有仓库、代码不开源，第三方无法审计实现，只能看本页脱敏界面和机制描述
  • 对话质量依赖所配模型：弱模型偶发空产出、限流，需要重试与降级兜底，兜底逻辑本身还在修

  • Tauri 桌面端与网页端双轨演进，两边体验要同步验证，成本比单端高
